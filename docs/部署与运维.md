# 本地开发与运行

项目定位为本地桌面应用，不提供服务器部署指南。开发模式由 Web、Local API、SQLite 和用户本机的 Codex CLI 组成。

面向已安装 Codex Desktop 的 Windows 用户，请优先阅读 [Windows 源码安装与启动](../INSTALL.md)。该文档定义了 Codex 可自动执行的项目内步骤，以及系统软件安装、PATH 修改和桌面快捷方式必须先征得用户确认的边界。

## 前置条件

- Node.js 22.13+
- pnpm 11+
- Git
- 已安装并自行登录的 Codex CLI

验证 Codex CLI：

```bash
codex --version
```

登录失败或 CLI 不可用时，请使用 Codex 自身的安装与登录流程。本项目不接收账号密码，也不能代替 Codex 完成认证。

## 开发命令

```bash
pnpm install
pnpm typecheck
pnpm test
pnpm build
pnpm desktop:pack
pnpm codex:probe
```

Windows 开发脚本：

```powershell
.\scripts\dev.ps1 -Target all -Action start
.\scripts\dev.ps1 -Target all -Action status
.\scripts\dev.ps1 -Target api -Action logs
.\scripts\dev.ps1 -Target all -Action stop
```

开发日志和进程状态保存在 Git 忽略的 `.runtime/dev/`。脚本只管理由自身启动且身份匹配的进程，不应终止占用同一端口的其他程序。

## 启动检查

1. 确认 Local API 只监听 `127.0.0.1`。
2. 确认健康检查可响应。
3. 确认 `CodexProvider` 已连接，而不只是 HTTP 服务已启动。
4. 确认 SQLite 数据目录可写，且未落入 Git 跟踪范围。
5. 确认首次同步完成后再判断任务是否缺失。

## 故障处理

### Provider 未连接

- 检查 `codex --version`。
- 在独立终端确认 Codex CLI 已登录并可正常使用。
- 检查 `CODEX_BIN` 是否指向有效可执行文件。
- 查看 Local API 日志中的启动、超时和重连信息，分享前先脱敏。

### 任务显示失联或未知

失联表示观测台长时间没有获得新事实，不等于 Agent 仍在运行或已经失败。先刷新 Provider 连接，再检查本机 rollout 是否仍更新；不要通过修改数据库强制伪造完成状态。

### SQLite 无法打开

- 确认数据目录存在且当前用户可写。
- 确认没有把数据库放在只读安装目录、网络盘或同步冲突目录。
- 备份数据库文件后再执行修复或迁移。
- 不要在应用运行时直接用第三方工具写数据库。

## 发布边界

仓库已提供 Windows、macOS 和 Linux 构建配置与 GitHub Release workflow。正式发布前必须完成：

- SQLite 新装与升级迁移测试。
- 安装包签名、哈希和软件物料清单检查。
- 三个平台的启动、数据目录、Codex 发现和卸载验证。
- 确认安装包不包含开发日志、本机数据、`.env` 或测试凭据。
- 在 GitHub 发布 Release；Gitee 仅同步源码和必要的发布说明。

当前尚未发布签名安装包，不应把开发服务直接暴露到公网、局域网共享地址或反向代理。
