# 架构决策

本页记录长期有效的重要取舍。每项决策包含状态、背景、决策和影响。

## ADR-001：Provider 抽象先行

- 状态：已接受
- 背景：不同 AI Agent Runtime 的任务、事件和状态协议不同，界面不应绑定单一实现。
- 决策：通用领域模型只表达任务、运行、事件、输出和 capability；Provider 专有字段在适配层转换。当前仅实现 `CodexProvider`。
- 影响：接入新 Provider 需要独立适配器和契约测试，不能通过在通用对象中堆叠可选专有字段快速接入。

## ADR-002：本地优先桌面应用

- 状态：已接受
- 背景：任务提示词、源码路径、命令和输出具有较高敏感性，远程服务会显著扩大隐私与安全责任。
- 决策：核心功能在用户电脑运行，Local API 默认只监听 loopback，不建设账号体系、云端控制台或后台任务托管。
- 影响：跨设备同步和团队协作不属于当前范围；跨平台桌面生命周期和本机权限控制成为发布质量重点。

## ADR-003：SQLite 为唯一持久化方案

- 状态：已接受并实现
- 背景：要求用户安装外部数据库会增加使用门槛，也不符合单用户本地应用定位。
- 决策：桌面版使用嵌入式 SQLite 保存查询模型、运行、事件和输出快照，不支持外部数据库配置。
- 影响：使用版本化迁移、事务、WAL 和启动恢复；备份恢复界面与数据库损坏诊断仍需在正式 Release 前补齐。

## ADR-004：Codex 认证归用户管理

- 状态：已接受
- 背景：复制或代理 Codex 登录会引入凭据保管、账号安全和兼容性风险。
- 决策：用户自行安装并登录 Codex CLI；观测台只调用本机 `codex app-server`，不读取账号密码、Token 或 Cookie。
- 影响：未安装或未登录时提供清晰诊断，但不得引导用户把秘密粘贴到观测台或 Issue。

## ADR-005：GitHub 主仓，Gitee 镜像

- 状态：已接受
- 背景：需要兼顾公开协作、Release 生态与国内代码访问体验。
- 决策：GitHub 承载主分支、Issue、Pull Request、Release 和安全报告；Gitee 作为只读或延迟同步镜像。
- 影响：贡献者只在 GitHub 提交 Issue 与 Pull Request，避免双向修改造成历史分叉。

## ADR-006：全局任务与受管任务分层观测

- 状态：已接受
- 背景：独立进程无法可靠恢复其他客户端未持久化的完整事件，但观测台发起的任务可以稳定关联运行标识。
- 决策：全局任务只承诺 Provider 可见的轻量状态；受管任务记录细粒度事件、输出和指标。界面必须明确展示观测能力差异。
- 影响：未知字段保持为空或未知，不从标题、时间和窗口状态推断运行事实。

## ADR-007：无默认遥测

- 状态：已接受
- 背景：即使匿名遥测也可能泄露使用时间、目录模式或任务特征。
- 决策：默认不收集遥测、崩溃报告和使用分析。未来如引入，必须另行评审，并满足关闭默认值、明确授权、字段公开和发送前可见。
- 影响：项目维护主要依赖用户主动提交的脱敏 Issue、诊断信息和测试结果。

## ADR-008：使用 Electron 封装桌面应用

- 状态：已接受并实现
- 背景：现有 React、Fastify 与 Node Provider 适配层需要在三个桌面平台复用，并直接使用 Node 内置 SQLite。
- 决策：Electron 主进程在同一进程内启动 Local API，生产态使用随机回环端口并托管 Web 静态资源；渲染进程禁用 Node 集成、启用 sandbox，并拒绝非本机导航。
- 影响：安装包体积高于系统 WebView 方案，但不需要额外 Rust 工具链，现有 Node 能力可直接复用；发布前必须持续跟进 Electron 安全更新与平台签名要求。
