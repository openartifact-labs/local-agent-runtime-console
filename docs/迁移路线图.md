# 开源桌面版迁移路线图

本文档用于区分已存在的原型能力与开源桌面版尚未完成的工作，避免 README 和 Release 对成熟度作出错误承诺。

## 阶段一：仓库净化与边界固化

- [x] 建立独立 GitHub 主仓库与 Gitee 镜像。
- [x] 采用 Apache License 2.0。
- [x] 建立中文开源文档、贡献、安全和隐私规则。
- [x] 清理历史品牌、私有地址、个人路径和旧包名。
- [ ] 建立敏感信息与依赖许可证扫描。

## 阶段二：本地持久化

- [x] 用 SQLite repository 替换历史持久化实现。
- [x] 定义系统应用数据目录和开发数据目录。
- [x] 建立版本化迁移、事务和启动恢复机制。
- [ ] 增加新装、跨版本升级、备份恢复和损坏场景测试。
- [x] 确保源码、日志和构建产物默认不包含用户数据库。

## 阶段三：桌面封装

- [x] 确定 Electron 桌面运行时并记录 ADR。
- [x] 管理 Local API、Web 和 Provider 生命周期。
- [ ] 提供首次启动、Codex CLI 检测、数据目录和诊断界面。
- [x] 限制外部导航、文件访问和渲染进程权限。
- [ ] 完成 Windows、macOS、Linux 的安装与卸载验证。

## 阶段四：发布工程

- [x] 建立 GitHub Actions 的跨平台构建与 Release 制品流水线。
- [ ] 生成签名、SHA-256 校验值和软件物料清单。
- [ ] 提供中文安装说明、升级说明和已知限制。
- [ ] 发布首个预览版，并在真实设备上验证数据迁移。
- [ ] 稳定后发布 `1.0.0`。

## 稳定版门槛

首个稳定版至少满足：

1. 不需要外部数据库或维护者提供的在线服务。
2. 不读取、保存或上传 Codex 登录凭据。
3. SQLite 升级失败时能够停止并保护旧数据。
4. 三个平台的安装包来源、签名或哈希可验证。
5. 全局任务与受管任务的可见能力在界面中清晰区分。
6. 仓库通过个人信息、秘密和第三方许可证检查。

## 暂不纳入

- 团队空间、多租户和远程管理。
- 云端数据库与跨设备同步。
- 企业级部署、单点登录和权限中心。
- Codex 账号托管或平台代理登录。
